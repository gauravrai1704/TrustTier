Anjana, Kumari, Peri, Rathor, & Somani (2019), "An efficient framework for optimistic concurrent execution of smart contracts" (PDP 2019)
This is the real deal for your concurrency section. It's an actual academic framework for optimistic concurrency control (OCC) applied specifically to smart contract execution — which is exactly the technique concurrency_sim.py implements (model each transaction's read/write set, detect conflicts, schedule non-conflicting ones together). Right now your README justifies the OCC approach by informally gesturing at "Block-STM-style" research; this paper is a far more precise, directly-on-topic citation, since it's specifically about smart contracts rather than a general blockchain (Aptos/Move). This should replace or sit alongside the informal Block-STM mention.
Zareh Chahoki et al. (2025), "Conthereum: Concurrent Ethereum Optimized Transaction Scheduling for Multi-Core Execution" (BRAINS 2025)
Even more directly on point — this is concurrent transaction scheduling, specifically for Ethereum (which is exactly your target chain, unlike Aptos/Sui-style Block-STM papers), and it's very recent (2025).
